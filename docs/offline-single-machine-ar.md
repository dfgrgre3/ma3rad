# التشغيل على جهاز واحد بدون إنترنت — CeramiSys ERP

هذا المستند يوضح كيف يعمل النظام كتطبيق سطح مكتب مستقل على جهاز واحد (Single Machine)
دون أي اتصال بالإنترنت، وما التغييرات التي أُجريت في الشيفرة لضمان ذلك.

## 1. طبيعة النظام

- تطبيق Electron لسطح المكتب (Windows x64) — لا يوجد خادم ويب ولا API مركزي.
- قاعدة البيانات SQLite تُدار داخل التطبيق (`sql.js`) وتُحفظ في ملف مشفّر على القرص.
- الخطوط (`@fontsource/cairo`) والصور والأيقونات كلها مضمّنة داخل الحزمة.
- لا توجد خدمة سحابية، ولا حساب مستخدم خارجي، ولا مزامنة بين أجهزة.

```
مثبّت واحد  →  جهاز واحد  →  ملف قاعدة بيانات واحد
```

### ضمانات فرض «جهاز واحد» داخل الشيفرة

| الضمان | مكان التنفيذ | ما يمنعه |
| --- | --- | --- |
| قفل نسخة واحدة `requestSingleInstanceLock` | `electron/main.js` | تشغيل نسختين على نفس الجهاز تفتحان ملف قاعدة البيانات نفسه وتتلفانه |
| فتح النافذة الحالية عند تشغيل ثانٍ | حدث `second-instance` | فتح نافذة/قاعدة بيانات موازية |
| تحميل ملفات محلية فقط في النسخة المثبّتة | `win.loadFile` | تحميل واجهة من عنوان شبكي |
| حارس الشبكة `installOfflineNetworkGuard` | `session.defaultSession` | أي طلب HTTP/HTTPS خارج الجهاز (يبقى منفذ Vite المحلي للتطوير فقط) |
| منع التنقل والنوافذ الجديدة | `will-navigate` + `setWindowOpenHandler` | فتح واجهات خارجية داخل التطبيق |
| قاعدة بيانات واحدة محلية | `%APPDATA%\CeramiSysERP\data\ceramisys.sqlite` | أي تخزين سحابي أو مشترك |
| لا حزم خادم/مزامنة | `package.json` | express/socket.io/axios/firebase… إلخ |
| لا استدعاءات شبكة من الواجهة | `src/**` | `fetch`/`XMLHttpRequest`/`WebSocket`/مزامنة سحابية |

كل ما سبق مُتحقَّق آليًا في `test/single-device.test.ts`، وأي إضافة مستقبلية لحزمة خادم أو استدعاء شبكة من الواجهة تُفشل الاختبار.

الاستثناءات الوحيدة المسموحة:

- **الطباعة على طابعة شبكية داخل نفس الشبكة المحلية** (منفذ TCP 9100) — طباعة فقط، ولا تنقل بيانات بين أجهزة.
- **فتح رابط واتساب** بإجراء صريح من المستخدم عبر المتصفح الخارجي — لا يزامن أي بيانات، ويعمل بدون إنترنت بنسخ النص فقط.

## 2. ما تم تعديله لضمان العمل بدون إنترنت

| التعديل | الملف | الأثر |
| --- | --- | --- |
| حزمة `xlsx` لم تُعد تُحمَّل من CDN خارجي، بل من أرشيف محلي `vendor/xlsx-0.20.3.tgz` | `package.json`, `package-lock.json`, `vendor/` | إعادة التثبيت والبناء تعمل بدون إنترنت |
| إزالة اعتماد `electron-updater` غير المستخدم | `package.json` | لا توجد أي محاولة تحديث تلقائي عبر الشبكة |
| إضافة "حارس الشبكة" في العملية الرئيسية يمنع أي طلب HTTP/HTTPS خارج الجهاز | `electron/main.js` | التطبيق لا يتصل بالإنترنت إطلاقًا؛ الطلبات الخارجية تُلغى بدل أن تتعلّق أو تفشل بصمت |
| مشاركة واتساب تتحقق من وجود اتصال قبل الفتح وتنسخ نص الرسالة عند عدم الاتصال | `src/utils/externalLinks.ts` + 5 شاشات | لا فشل صامت، والميزة الأساسية غير متأثرة |
| سياسة CSP صارمة عند البناء (`script-src 'self'` بدون `unsafe-inline`) | `vite.config.ts` | لا يمكن تحميل أي سكربت خارجي |

الميزة الوحيدة التي تحتاج إنترنت هي **إرسال مستند عبر واتساب**، وهي اختيارية بالكامل
وتبقى معطّلة بأمان على جهاز غير متصل.

## 3. متطلبات الجهاز

- Windows 10/11 بنسخة 64-bit.
- مساحة تخزين كافية (المثبّت ≈ 140 MB + مساحة البيانات والنسخ الاحتياطية).
- لا حاجة إلى Node.js أو npm أو أي أدوات تطوير على جهاز التشغيل.
- لا حاجة إلى اتصال بالإنترنت، ولا صلاحيات شبكة، ولا فتح منافذ.

## 4. التثبيت على الجهاز الوحيد

1. انسخ الملف `release\CeramiSys ERP Setup 1.1.3.exe` إلى الجهاز (USB أو قرص داخلي).
2. شغّل الملف واختر مجلد التثبيت، ثم أكمل التثبيت.
3. افتح الاختصار "CeramiSys ERP" من سطح المكتب أو قائمة ابدأ.
4. أكمل معالج الإعداد الأولي: بيانات المعرض، الفرع، ثم حساب المدير وكلمة المرور.
5. غيّر كلمة المرور الافتراضية عند أول دخول.

> يُسمح بنسخة واحدة تعمل في الوقت نفسه: التطبيق يستخدم قفل نسخة واحدة
> (`requestSingleInstanceLock`)، وأي تشغيل ثانٍ ينقل التركيز إلى النافذة المفتوحة.

### التثبيت الصامت (اختياري)

```
"CeramiSys ERP Setup 1.1.3.exe" /S
```

## 5. مواقع البيانات والنسخ الاحتياطي

| المحتوى | المسار |
| --- | --- |
| قاعدة البيانات | `%APPDATA%\CeramiSysERP\data\ceramisys.sqlite` |
| النسخ الاحتياطية | `%APPDATA%\CeramiSysERP\backups\` |
| بيانات تسجيل الدخول المحفوظة | `%APPDATA%\CeramiSysERP\remembered-login.enc` |

- أنشئ نسخة احتياطية من داخل التطبيق قبل أي تحديث أو نقل للجهاز.
- للاستعادة: أغلق التطبيق، استبدل ملف `ceramisys.sqlite` بنسخة سليمة، ثم أعد التشغيل.
- نقل النظام إلى جهاز جديد = نسخ الملفين أعلاه (قاعدة البيانات + النسخ الاحتياطية) يدويًا.

## 6. التحديث في بيئة بلا إنترنت

لا يوجد تحديث تلقائي عن بُعد. لتحديث نسخة:

1. أنشئ المثبّت الجديد على جهاز مطوّر (انظر القسم 7).
2. انقله إلى الجهاز عبر وسيط تخزين، وأنشئ نسخة احتياطية أولًا.
3. شغّل المثبّت الجديد فوق القديم بنفس مسار التثبيت — بياناتك في `%APPDATA%` لا تُمس.

## 7. إعادة البناء بالكامل بدون إنترنت (جهاز المطوّر)

بعد إزالة اعتماد CDN، يمكن تجهيز المشروع مرة واحدة ثم البناء دون اتصال:

```powershell
# مرة واحدة، مع توفر إنترنت (أو نسخ node_modules الجاهز من جهاز آخر)
npm install --no-audit --no-fund

# لاحقًا بدون إنترنت
npm run build          # بناء واجهة React إلى dist/
npm run electron:dist  # إنتاج المثبّت في release/ عبر electron-builder
```

ملاحظات:

- `electron-builder` يحتاج إلى تخزين Electron المؤقت محليًا (`%LOCALAPPDATA%\electron\Cache`)
  وملفات NSIS (`%LOCALAPPDATA%\electron-builder\Cache`). إذا كانت موجودة مسبقًا يعمل البناء بلا شبكة.
- لنقل المشروع إلى جهاز بناء آخر بدون إنترنت: انسخ `node_modules/` و`vendor/` مع المشروع،
  ثم شغّل `npm run build && npm run electron:dist` مباشرة.
- ملف `vendor/xlsx-0.20.3.tgz` مطلوب لأي `npm ci` لاحق؛ لا تحذفه.

## 8. استكشاف الأخطاء

| الأعراض | السبب المحتمل | الحل |
| --- | --- | --- |
| لا يفتح التطبيق عند الضغط على الاختصار | نسخة أخرى تعمل | أغلق العملية من Task Manager ثم أعد الفتح |
| رسالة "مشاركة واتساب تحتاج اتصالاً بالإنترنت" | الجهاز غير متصل — سلوك متوقع | نُسخ نص الرسالة إلى الحافظة، استخدمه عند توفر اتصال |
| نافذة بيضاء عند التشغيل | ملفات `dist` تالفة أو نسخة غير مكتملة | أعد تثبيت المثبّت الرسمي |
| بطء في الحفظ مع بيانات كبيرة | حفظ كامل لقاعدة البيانات في كل مرة | راجع `docs/offline-single-machine-ar.md` وأحجام القاعدة، وقلّل النسخ الاحتياطية المتزامنة |
| "Unauthorized IPC caller" في السجل | محاولة تحميل الواجهة من أصل غير مسموح | شغّل التطبيق المثبّت فقط، لا تفتح `dist/index.html` في المتصفح |
