# توثيق صفحات المنصة — الجزء B (إدارة المنصة/SaaS Owner)

توثيق تفاعلي لصفحات لوحة مالك المنصة (`/platform/*`) في تطبيق React + TypeScript. كل عنصر تفاعلي موثّق بتسمية واجهته العربية/الإنجليزية وما يفعله فعلياً (مودال، تنقّل، استدعاء خدمة، تغيير تبويب...).

> ملاحظة عامة: معظم الصفحات تقرأ من مصدرين — «محلي» (`platformAdminService`) أو «مركزي» (`centralPlatformClient`) حسب إعداد مصدر البيانات، وعناصر كثيرة تُخفى/تُعطّل حسب صلاحيات المستخدم (`canPlatform(...)`). كل الإجراءات تنتهي بـ toast نجاح/خطأ.

## `/platform/support` — مركز الدعم الفني للمنصة

- **الملف:** `src/pages/platform/PlatformSupportPage.tsx` (+ مجلد `PlatformSupportPage/` للمكونات الفرعية)
- **الوصف:** إدارة تذاكر الدعم الفني للعملاء (Master/Detail view): قائمة تذاكر + تفاصيل المحادثة + الوصول عن بُعد + تقييم رضا العميل ومتابعة SLA.
- **العناصر التفاعلية:**
  - زر «تذكرة دعم جديدة» (بالـ header) ← يفتح مودال `NewTicketModal` (يتطلب `platform.support.update`).
  - حقل بحث «ابحث برقم التذكرة أو عنوانها...» + فلتر «الحالة» (كل الحالات/مفتوحة/قيد المعالجة/بانتظار العميل/تم الحل/مغلقة) + فلتر «الأولوية» (عاجل/مرتفع/متوسط/منخفض) ← يصفّي قائمة التذاكر.
  - بطاقة تذكرة في القائمة ← نقرة واحدة تختارها وتحمّل تفاصيلها (رسائل + جلسات عن بُعد).
  - في ترويسة التفاصيل:
    - قائمة «الحالة» (مفتوحة/قيد المعالجة/بانتظار العميل/تم الحل/مغلقة) ← يغيّر حالة التذكرة فوراً.
    - قائمة «الأولوية» (منخفض/متوسط/مرتفع/عاجل) ← يغيّر أولوية التذكرة.
    - حقل «مسؤول» (onBlur) ← يعيّن الموظف المسؤول عن التذكرة.
    - زر «تقييم» (يظهر فقط للتذكرة المحلولة وبدون تقييم) ← يفتح مودال `RatingModal`.
  - قسم «الوصول عن بُعد للعميل»:
    - زر «طلب وصول عن بُعد» ← يطلب وصولاً عن بُعد من العميل (60 دقيقة).
    - زر «الموافقة على الوصول» ← يوافق على طلب الوصول المعلّق.
    - رابط «إلغاء الطلب» ← يلغي طلب الوصول.
    - زر «بدء جلسة الاتصال» ← يفتح مودال `RemoteSessionModal`.
    - لكل جلسة نشطة: زر «إنهاء الجلسة» ← يطلب ملخصاً (prompt) ثم ينهي الجلسة.
  - شريط «ردود جاهزة» (Canned Replies) ← نقرة على أي رد تدرجه في صندوق الكتابة.
  - خانة «رسالة داخلية فقط» ← تجعل الرسالة داخلية (لا تظهر للعميل، تظهر بخلفية كهرمانية).
  - زر إرسال (يظهر كـ «إرسال للعميل» أو «إرسال داخلي») ← يرسل الرسالة المرفق رابطها.
  - مودال «إنشاء تذكرة دعم جديدة»: حقول العميل/العنوان/الأولوية (SLA)/الموظف/الوصف + زرّا «إلغاء» و«إنشاء التذكرة».
  - مودال «بدء جلسة وصول عن بُعد»: اسم الفني + مدة الجلسة (15–180 دقيقة) + «إلغاء» و«بدء جلسة الاتصال».
  - مودال «تقييم رضا العميل»: نقر النجوم (1–5) + ملاحظات + «إلغاء» و«حفظ التقييم».

## `/platform/devices` — إدارة الأجهزة

- **الملف:** `src/pages/platform/PlatformDevicesPage.tsx`
- **الوصف:** جدول الأجهزة المفعّلة عبر العملاء: Hardware ID، نظام التشغيل، آخر اتصال، الحالة، وأدوات إيقاف/تحرير/إلغاء استنساخ.
- **العناصر التفاعلية:**
  - زر «كشف الاستنساخ» (ghost، بالـ header) ← يفحص تكرار Hardware ID (محلياً أو عبر API مركزي) ويعرض تنبيهات في لوحة «تنبيهات الاستنساخ».
  - حقل بحث «Hardware ID أو الاسم أو نظام التشغيل...» ← يصفّي الجدول.
  - إجراءات كل صف (أيقونات):
    - «إيقاف/تفعيل» (أيقونة Cpu، محلي فقط) ← يبدّل حالة الجهاز ACTIVE/SUSPENDED مباشرة.
    - «إيقاف عن بُعد» (أيقونة ShieldAlert، للأجهزة ACTIVE) ← يفتح مودال تأكيد «إيقاف الجهاز عن بُعد».
    - «تحرير الربط» (أيقونة Link، للأجهزة المرتبطة بترخيص) ← يفتح مودال «تحرير الجهاز عن بُعد».
    - «إلغاء الجهاز» (أيقونة ShieldX، لغير الملغاة) ← يفتح مودال «إلغاء الجهاز عن بُعد».
    - «حذف التفعيل» (أيقونة Cpu، محلي فقط، بتأكيد window.confirm) ← يحذف تفعيل الجهاز.
  - مودال تأكيد الإجراء: زرّا «إلغاء» و«تأكيد الإيقاف/التحرير/الإلغاء» (danger) ← ينفّذ الإجراء على السيرفر.

## `/platform/admin-control` — مركز التحكم الإداري (RBAC & Staff Console)

- **الملف:** `src/pages/platform/PlatformAdminControlPage.tsx`
- **الوصف:** فصل بين إدارة موظفي المنصة (Platform Staff) ومستخدمي الشركات العميلة (Tenant Users) عبر تبويبين رئيسيين.
- **العناصر التفاعلية:**
  - تبويبان: «إدارة موظفي المنصة (Platform Staff Management)» و«إدارة مستخدمي الشركات العميلة (Tenant Admin & Users)».
  - **تبويب الموظفين:**
    - بحث «الاسم أو البريد أو الهاتف...» + قائمة «الأدوار الوظيفية» ← تصفية.
    - زر «إضافة موظف منصة جديد» ← يفتح مودال إضافة/تعديل موظف.
    - كل صف: أيقونة «تعديل الموظف» (تفتح المودال للتعديل)، «تعطيل/تنشيط الحساب» (Lock/Unlock)، «حذف الموظف» (تأكيد ثم حذف) — لا تظهر لأدوار محدودة/مالك المنصة.
    - مودال «إضافة/تعديل موظف»: الاسم، البريد، الهاتف، الدور الوظيفي (لا يُعدَّل لدور SUPER_ADMIN)، كلمة المرور + «إلغاء»/«حفظ الموظف».
  - **تبويب مستخدمي العملاء:**
    - قائمة «اختر الشركة العميلة» ← يحمّل مستخدمي تلك الشركة.
    - زر «إضافة مستخدم للعميل» ← يفتح مودال إضافة/تعديل مستخدم.
    - كل صف: «تعديل المستخدم»، «تعطيل/تنشيط الحساب»، «حذف المستخدم» (تأكيد).
    - مودال «إضافة/تعديل مستخدم»: الاسم، Username، البريد، الدور في ERP (مدير/فرع/محاسب/مبيعات/كاشير/مستودع)، الهاتف + «إلغاء»/«حفظ المستخدم». إنشاء مستخدم جديد يولّد كود دعوة/كلمة مرور مؤقتة تُعرض في toast.

## `/platform/security-center` — مركز الأمان المركزي

- **الملف:** `src/pages/platform/PlatformSecurityCenterPage.tsx` + مجلد `PlatformSecurityCenterPage/` (TabsBar, OverviewTab, SessionsTab, LoginsTab, KeysTab, IncidentsTab, IpBansTab, IncidentModal, ApiKeyModal, ApiKeyResultModal, OwnerAccountsSection, SecurityHero)
- **الوصف:** لوحة مراقبة أمنية للمنصة: درجة أمان، جلسات، سجل دخول، مفاتيح API/توقيع، حوادث، وحظر IP.
- **العناصر التفاعلية:**
  - أزرار الـ header: «تحديث» (يعيد تحميل كل البيانات) و«إنهاء كافة الجلسات النشطة» (confirm ثم إنهاء كل جلسات الموظفين).
  - بطاقة «SecurityHero» تعرض درجة الأمان ومؤشرات 2FA/الجلسات/فشل الدخول/الحوادث — عرض فقط.
  - `OwnerAccountsSection`: جدول حسابات «مالك المنصة» (الحالة/الاعتماد) — عرض فقط للمالك.
  - تبويبات `TabsBar`: «نظرة عامة والإنذارات»، «الجلسات المركزية والأجهزة الموثوقة (n)»، «سجل محاولات الدخول والأنشطة»، «مفاتيح API والتوقيع الرقمي»، «سجل الحوادث والاستجابة (n)»، «حظر عناوين IP».
  - **تبويب النظرة العامة:**
    - زر «اجعلها إلزامية / اجعلها اختيارية» (في بطاقة سياسة 2FA) ← يبدّل إلزامية المصادقة الثنائية.
    - لكل حادث مفتوح في بانر الإنذارات: زر «إغلاق وحل الحادث» ← يطلب ملخصاً (prompt) ثم يحلّه.
  - **تبويب الجلسات:** زر «إنهاء كافة الجلسات الأخرى» + لكل جلسة (غير الجلسة الحالية) زر «إنهاء الجلسة» (confirm).
  - **تبويب سجل الدخول:** بحث بالبريد/IP + خانة «عرض المحاولات الفاشلة والمحظورة فقط» ← تصفية (عرض فقط).
  - **تبويب المفاتيح:**
    - لكل مفتاح توقيع: زر «تدوير المفتاح» (confirm).
    - زر «إنشاء مفتاح API جديد» ← يفتح `ApiKeyModal`.
    - لكل مفتاح API نشط: «تدوير» (confirm + يولّد مفتاحاً جديداً ويعرضه في `ApiKeyResultModal`) و«إلغاء» (confirm).
    - مودال «إنشاء مفتاح API تجاري مركزي»: اسم المفتاح، العميل، الصلاحيات (scopes)، تاريخ الانتهاء + «إنشاء المفتاح الآن».
    - مودال نتيجة المفتاح: زر «نسخ» (ينسخ المفتاح الصريح للحافظة) و«لقد قمت بحفظ المفتاح بأمان، إغلاق».
  - **تبويب الحوادث:** زر «تسجيل بلاغ أمني يدوي» ← يفتح `IncidentModal`؛ لكل حادث غير محلول: «إغلاق كـ محلول» (prompt لملخص الإجراء).
    - مودال «تسجيل بلاغ أمني جديد»: عنوان البلاغ، النوع، مستوى الخطورة، تفاصيل، مصدر IP + «تسجيل البلاغ».
  - **تبويب حظر IP:** نموذج (عنوان IP أو CIDR + سبب + انتهاء اختياري) وزر «حظر» (confirm)؛ في الجدول: «فك الحظر» لكل عنوان نشط (confirm). متاح فقط في الوضع المركزي.

## `/platform/staff` — مركز التحكم في حسابات الإدارة

- **الملف:** `src/pages/platform/PlatformStaffPage.tsx` + مجلد `PlatformStaffPage/` (AccountsTab, SessionsTab, InvitesTab, LoginsTab, SecurityTab + 6 مودالات)
- **الوصف:** إدارة شاملة لموظفي المنصة: حسابات، جلسات وأجهزة موثوقة، دعوات بريد، سجل دخول، ومصادقة ثنائية TOTP.
- **العناصر التفاعلية:**
  - أزرار الـ header: «مصفوفة الأدوار والصلاحيات» (ينقل إلى `/platform/roles`) و«إضافة موظف» (يفتح مودال إنشاء).
  - تبويبات: «الحسابات»، «الجلسات والأجهزة»، «الدعوات»، «سجل الدخول»، «المصادقة والأمان».
  - **تبويب الحسابات:**
    - بطاقات الأدوار الستة ← نقرة تبدّل فلتر الدور (نقرة ثانية تلغيه).
    - بحث «الاسم، البريد أو الهاتف...» + قائمة «جميع الأدوار».
    - إجراءات كل موظف: «تعديل البيانات» (مودال)، «إعادة تعيين كلمة المرور» (مودال)، «فرض/إلغاء فرض تغيير كلمة المرور»، «نقل الصلاحيات إلى موظف آخر» (مودال)، «نطاق البيانات (العملاء المرئيون)» (مودال)، «تجميد الحساب + إنهاء جلساته» / «تفعيل الحساب»، «حذف منطقي» (confirm).
    - مودال «تعديل/إضافة موظف»: الاسم، البريد، الهاتف، الدور الإداري، كلمة المرور الأولية + «حفظ التعديلات»/«إضافة الموظف».
    - مودال «إعادة تعيين كلمة المرور»: كلمة مرور جديدة + تأكيد + «إعادة التعيين».
    - مودال «نقل صلاحيات»: اختيار الموظف الهدف + ملاحظة تدقيق + «نقل الصلاحيات» (يُنسخ الدور والتجاوزات والنطاق وينهي جلسات الهدف).
    - مودال «نطاق البيانات»: خيار «كل العملاء» أو «عملاء محددون» + قائمة عملاء + بحث + «حفظ النطاق».
  - **تبويب الجلسات والأجهزة:**
    - زر «وثّق هذا الجهاز» (إن لم يكن موثوقاً) / شارة «هذا الجهاز موثوق».
    - زر «إنهاء كل الجلسات الأخرى» (confirm).
    - لكل جلسة: زر «إنهاء الجلسة». لكل جهاز موثوق: زر «إلغاء التوثيق».
  - **تبويب الدعوات:**
    - نموذج دعوة: الاسم، البريد، الهاتف، الدور (بدون SUPER_ADMIN)، صلاحية الرابط (24 ساعة/72 ساعة/أسبوع/30 يوماً) + زر «إنشاء دعوة».
    - بعد الإنشاء: رابط الدعوة يظهر مرة واحدة + زر «نسخ الرابط».
    - لكل دعوة في القائمة: زر «إلغاء الدعوة».
  - **تبويب سجل الدخول:** مفتاح «الفاشلة/المحظورة فقط» (Toggle) ← يصفّي جدول المحاولات (عرض فقط).
  - **تبويب المصادقة والأمان:**
    - زر «تفعيل المصادقة الثنائية» (بدء إعداد TOTP: QR + مفتاح سري + رموز استرداد) أو «تعطيل المصادقة الثنائية» (مودال بكود تحقق).
    - مودال التفعيل: إدخال كود التحقق (6 أرقام) + إقرار حفظ رموز الاسترداد + «تأكيد وتفعيل».
    - مودال التعطيل: كود التحقق + «تعطيل».
    - بطاقات سياسة «متوقفة / اختيارية / إلزامية» ← نقرة تبدّل سياسة إلزام 2FA للمنصة.
    - لكل موظف بلا 2FA في قائمة الامتثال: زر «إعادة تعيين المصادقة الثنائية» (confirm).

## `/platform/roles` — مصفوفة الأدوار والصلاحيات

- **الملف:** `src/pages/platform/PlatformRolesPage.tsx`
- **الوصف:** مصفوفة صلاحيات تفاعلية: أقسام × أفعال (عرض/إنشاء/تعديل/حذف/اعتماد/تصدير) + عمليات خاصة، لكل دور من 6 أدوار. مالك المنصة لا يُعدَّل.

  - زر «تجاهل (n)» ← يتجاهل التغييرات غير المحفوظة ويعيد التحميل (يظهر فقط عند وجود تعديلات).

  - بطاقات ملخص الأدوار (عدد الصلاحيات لكل دور) — عرض فقط.
  - في رأس «المصفوفة الأساسية»: لكل دور (ما عدا SUPER_ADMIN) زرا «الكل+» و«الكل−» ← يمنح/يسحب كل صلاحيات الأفعال القياسية للدور.
  - كل خانة checkbox في الجدولين ← تبدّل صلاحية محددة للدور.
  - وضع العرض فقط إن لم تملك صلاحية التعديل.

- **الوصف:** إدارة حزم التحديث: القنوات (STABLE/BETA/ALPHA/HOTFIX)، النشر، الأهداف لكل عميل، التراجع، والتعطيل.
- **العناصر التفاعلية:**
  - زر «إضافة إصدار جديد» ← يفتح مودال «إنشاء أو تحديث حزمة إصدار».

    - «العملاء» ← يفتح مودال «العملاء المستهدفون للإصدار x.x.x» لعرض/تحديد العملاء وتطبيقات التحديث.

  - مودال الإصدار: رقم الإصدار، القناة، رابط التحميل، بصمة SHA256، ملاحظات، خانة «تحديث إجباري» + «إلغاء» و«نشر الإصدار».

- **الوصف:** لوحات BI للمنصة: الإيرادات (MRR/ARR)، ديناميكية العملاء، الاشتراكات، التراخيص، والصحة التشغيلية — كلها تقارير عرضية.
- **العناصر التفاعلية:**
  - زر «تصدير التقرير CSV» ← ينزّل تقرير `platform-analytics-{period}.csv` بالمؤشرات.
  - زر «تحديث الأرقام» ← يعيد تحميل كل المقاييس.
  - أزرار الفترة: «7 أيام»، «30 يوماً»، «ربع سنوي»، «سنة كاملة» ← تبدّل فترة المقارنة.
  - قائمة «فلترة حسب الباقة» ← تصفية كل المؤشرات بباقة معينة.
  - باقي الصفحة بطاقات مؤشرات وعلامات دلتا % — عرض فقط.

## `/platform/sync` — مراقبة المزامنة المركزية

- **الملف:** `src/pages/platform/PlatformSyncMonitorPage.tsx`
- **الوصف:** سجل عمليات مزامنة الفروع/الأجهزة (offline-first) مع KPIs وحالات النجاح/الفشل/التعارض.
- **العناصر التفاعلية:**
  - زر «تشغيل مزامنة الآن» ← يستدعي عميل مزامنة سطح المكتب `window.ceramisys.sync.pullEvents` ويُسجّل النتيجة في السجل (يتطلب تطبيقاً سطح مكتب مهيأً).
  - زر «تحديث السجلات» ← يعيد التحميل.
  - قائمة «الحالة» (ناجحة/فاشلة/جزئية) + قائمة «المستأجر» ← تصفية.
  - لكل سجل: زر «إعادة» ← يعيد تشغيل مزامنة يدوية لذلك العميل.

## `/platform/backups` — النسخ الاحتياطية للمنشآت

- **الملف:** `src/pages/platform/PlatformBackupsPage.tsx`
- **الوصف:** نسخ احتياطية مركزة: نسخ خادم لكل منشأة + نسخ بيانات تطبيق ERP مشفرة على أجهزة العملاء مع طلبات استعادة عن بُعد.
- **العناصر التفاعلية (الوضع المركزي):**
  - قائمة «كل المنشآت» (فلتر عميل) + قائمة النوع «كاملة/تزايدية» + زر «طلب نسخة احتياطية» (confirm → ينشئ نسخاً على الخادم).
  - جدول النسخ: «تنزيل» (لكل نسخة مكتملة → يحمّل artifact كـ JSON) و«استعادة» (لكل نسخة مكتملة مرتبطة بعميل → confirm → طلب استعادة).
  - جدول «نسخ بيانات تطبيق المنشآت»: «طلب استعادة على الجهاز» (لكل نسخة جاهزة → confirm → الجهاز يطبقها عند اتصاله) و«إلغاء» (لإلغاء طلب استعادة معلّق).
- **العناصر التفاعلية (الوضع المحلي):**
  - زر «أخذ نسخة احتياطية فورية الآن» (confirm → نسخة مشفرة محلية + فحص سلامة) — الجدول عرض فقط.

## `/platform/integrations` — إدارة التكاملات المركزية

- **الملف:** `src/pages/platform/PlatformIntegrationsPage.tsx`
- **الوصف:** تكاملات المنصة بثلاث تبويبات: Webhooks، بوابات الدفع (Fawry/Paymob)، ومزود SMS. الأسرار تُخزّن على السيرفر وتُعرض مقنّعة.
- **العناصر التفاعلية:**
  - تبويبات: «نقاط الـ Webhooks (n)»، «بوابات الدفع الإلكتروني»، «مزود الرسائل النصية (SMS Gateway)».
  - **تبويب Webhooks:**
    - زر «إضافة Webhook جديد» ← يفتح مودال إضافة/تعديل.
    - لكل webhook: أيقونة نسخ المفتاح السري، «تعديل» (نفس المودال)، «اختبار» (يرسل حمولة تجريبية ويعرض HTTP status)، أيقونة حذف (confirm).
    - مودال Webhook: الاسم، رابط Endpoint، مفتاح سري اختياري، checkboxes الأحداث (إنشاء فاتورة/دفعة/تفعيل عميل/تجديد اشتراك/حادث أمني)، خانة «نشط» + «إلغاء» و«إنشاء وحفظ»/«تعديل وحفظ».
  - **تبويب الدفع:** حقول Fawry (Merchant Code، Security Key مقنّع readonly) وPaymob (Integration ID، Iframe ID، API Key مقنّع) + زر «حفظ إعدادات الدفع» (متاح في الوضع المركزي فقط).
  - **تبويب SMS:** قائمة المزود (Viomis/Twilio/Infobip)، Sender ID، API Token مقنّع، رصيد يومي، + زر «حفظ إعدادات الرسائل».

## `/platform/emergency` — مركز إجراءات الطوارئ (Killswitch)

- **الملف:** `src/pages/platform/PlatformEmergencyCenterPage.tsx`
- **الوصف:** إجراءات عزل طارئة خطيرة: إنهاء كل جلسات الموظفين، إعلان صيانة، إيقاف عميل فوراً، إلغاء مفاتيح API — كلها خلف مودال تأكيد بكلمة مفتاحية.
- **العناصر التفاعلية:**
  - بطاقة «إنهاء وتسجيل خروج كافة الموظفين فوراً» (danger) ← مودال تأكيد يتطلب كتابة `KILL-ALL-SESSIONS`.
  - زر «إعلان نافذة صيانة أمنية طارئة» ← يعرض toast نجاح (لا إجراء خلفي فعلي في الكود).
  - قائمة العملاء: لكل عميل غير موقوف زر «إيقاف وتجميد العميل فوراً» ← مودال تأكيد بكلمة `SUSPEND-TENANT` (يعلّق العميل).
  - قائمة مفاتيح API النشطة: لكل مفتاح زر «إلغاء فوري» ← مودال تأكيد بكلمة `REVOKE-KEY`.
  - مودال التأكيد العام: حقل إدخال كلمة التأكيد + «إلغاء وتراجع» و«تنفيذ الإجراء الطارئ» (معطّل حتى تطابق الكلمة المطلوبة).
  - (الإصدار `handleEmergencyDisableRelease` موجود في الكود لكن لا يوجد زر ظاهر له في الواجهة الحالية.)

## `/platform/plan-catalog` — منشئ الخطط والصفحات والمميزات

- **الملف:** `src/pages/platform/PlatformPlanWizardPage.tsx`
- **الوصف:** معالج من 5 خطوات لبناء محتوى باقة اشتراك: اختيار الخطة → الوحدات وصفحاتها → المميزات → إظهار/إخفاء صفحات موقع المستخدمين → المراجعة والتطبيق. يشمل إنشاء خطط ومميزات.
- **العناصر التفاعلية:**
  - مؤشر الخطوات الخمس (عرض فقط): «الخطة»، «الوحدات والصفحات»، «المميزات»، «إظهار وإخفاء الصفحات»، «المراجعة والتطبيق».
  - **الخطوة 0 — الخطة:**
    - زر «خطة جديدة» ← يفتح مودال «خطة اشتراك جديدة» (الاسم، الرمز، دورة الفوترة، الأسعار، أيام التجربة، حد المستخدمين، العملة، الوصف + «إنشاء الخطة»).
    - بطاقات الخطط ← نقرة تختار الخطة وتحمّل مسودتها.
  - **الخطوة 1 — الوحدات:** لكل وحدة `<details>` قابلة للطي + Toggle «مفعّلة في الباقة»؛ قائمة صفحات الوحدة تظهر داخلها (عرض فقط).
  - **الخطوة 2 — المميزات:**
    - بحث «في المميزات...» + زر «ميزة جديدة» ← يفتح مودال «ميزة جديدة/تعديل».
    - لكل ميزة: خانة «ضمن الخطة» (تضمينها بالباقة)، Toggle «مفعّلة» (تفعيل/تعطيل عام)، أيقونة «تعديل الميزة وصفحاتها»، أيقونة «حذف الميزة».
    - مودال الميزة: الاسم، الرمز (لا يُعدَّل بعد الإنشاء)، الفئة، نسبة الإتاحة %، الحد الأدنى لدرجة الخطة، الوصف + زر «اختيار الصفحات (n)» يفتح `PagePickerModal`، وToggles «Staging» و«مفعّلة» + «حفظ الميزة».
    - مودال اختيار الصفحات: بحث + لكل مجموعة زر «تحديد الكل/إلغاء الكل» + checkboxes الصفحات + «تم».
    - مودال «حذف الميزة» (تحذير) + «حذف نهائي».
  - **الخطوة 3 — إظهار/إخفاء الصفحات:** لكل صفحة checkbox «إظهار» مجمّعة حسب المجموعات + زر «إظهار الكل» (يمسح كل المخفي).
  - **الخطوة 4 — المراجعة:** ملخص (وحدات/مميزات/صفحات ظاهرة ومخفية) — عرض فقط.
  - شريط التنقل السفلي: «استعادة افتراضيات الباقة» (يعيد مسودة الخطة لمخزّنة)، «السابق»، «التالي»، وفي الخطوة الأخيرة «تطبيق على الباقة» (يحفظ الوحدات/المميزات + الصفحات المخفية في إعدادات الخطة).
