# إصدار وتحديث تطبيق سطح المكتب

## مصدر الإصدارات

تُوزّع التحديثات عبر GitHub Releases في `dfgrgre3/ma3rad`. يجب أن يتطابق
إصدار `package.json` مع وسم الإصدار `v<version>`؛ يعرض التطبيق الإصدار المثبّت
من Electron ويقارن به إصدار GitHub الأحدث. تُستخدم ملاحظات الإصدار المنشورة
كسجل تغييرات داخل التطبيق.

بعد تحديث رقم الإصدار وسجل التغييرات، تُبنى المنصة المستهدفة وتُنشر:

- Windows x64: `npm run electron:publish:x64`
- macOS: `npm run electron:publish:mac`
- Linux: `npm run electron:publish:linux`

تتطلب أوامر النشر صلاحية `GITHUB_TOKEN` لرفع أصول الإصدار. يتطلب Windows
شهادة Authenticode و`CERAMISYS_PUBLISHER_NAME` كما هو موضح في
[سياسة الأمان](./SECURITY.md). يتطلب macOS شهادة Developer ID وإعداد Apple
notarization في عامل البناء. Linux يحدّث AppImage؛ حزم deb لا تستخدم التحديث
الذاتي. لا تُضمّن مفاتيح أو شهادات في المستودع.

احتفظ بملفات التحديث التي ينتجها electron-builder، بما فيها ملفات YAML
و`blockmap`، إلى جانب المثبّت. يعتمد فحص سلامة التنزيل على SHA-512 في بيانات
التحديث، ويتحقق Windows أيضاً من توقيع الناشر المتوقع قبل تشغيل المثبّت.

## تجربة المستخدم وسلوك التحديث

- يفحص التطبيق عند التشغيل وكل ست ساعات.
- يبدأ تنزيل الإصدار الجديد تلقائياً في الخلفية، ويعرض الإصدار الحالي،
  والإصدار المتاح، وسجل التغييرات، وتقدم التنزيل.
- لا يُثبّت التحديث عند إغلاق التطبيق تلقائياً. يختار المستخدم «تثبيت وإعادة
  التشغيل»، ثم يحفظ التطبيق قاعدة البيانات، وينشئ نسخة مشفرة قبل التحديث،
  ويطلب تأكيد الإغلاق بالطريقة المعتادة.
- التحديث الاختياري يمكن تصغير إشعاره. لو وُسم الإصدار إلزامياً، يحجب التطبيق
  الواجهة حتى يكتمل التنزيل ويختار المستخدم التثبيت.
- فشل الفحص أو انقطاع الشبكة يبقي النسخة الحالية عاملة ويعرض إعادة المحاولة؛
  لا يُقبل ملف تنزيل غير مطابق للتجزئة أو، على Windows، للناشر المتوقع.

## الإصدارات الإلزامية

ضع `<!-- mandatory -->` في نص إصدار GitHub، أو ابدأ اسم الإصدار بـ
`[mandatory]`. خلاف ذلك يكون التحديث اختيارياً. لا تستخدم الوسم الإلزامي إلا
لإصلاحات أمنية أو توافقية تتطلب منع استمرار استخدام النسخة الحالية.

## التراجع والإصدارات السابقة

يُسمح للعميل بتثبيت إصدار أقدم إذا جُعل ذلك الإصدار أحدث إصدار Stable منشوراً
على GitHub. لإجراء التراجع، عيّن الإصدار السابق كـ Latest Release مع إبقاء
أصوله الموقعة وملفات التحديث متاحة، واستخدم شهادة الناشر نفسها على Windows.
سيكتشف العميل فرق الإصدار ويعرض التثبيت مثل أي تحديث آخر.

تُنشأ نسخة احتياطية مشفرة من قاعدة البيانات بعد تأكيد الحفظ وقبل التثبيت.
لاستعادتها من إصدار التطبيق، افتح «الإعدادات ← النسخ الاحتياطي ← فتح مجلد
نسخ الجهاز»، ثم اختر ملف `ceramisys_pre-update_*.sqlite.enc` في شاشة
الاستعادة؛ النسخة مرتبطة بمفتاح التشفير على الجهاز نفسه ولا تحتاج كلمة مرور.
مع ذلك، تراجع البرنامج لا يعكس ترحيلات قاعدة البيانات تلقائياً؛ يجب اختبار
توافق الإصدار الأقدم مع مخطط القاعدة، وإلا فاستعد النسخة الاحتياطية بإجراء
استعادة معتمد قبل تشغيل الإصدار الأقدم. غالباً يكون نشر إصدار إصلاح جديد برقم
أعلى أكثر أماناً من الرجوع الفعلي.

## قائمة تحقق الإصدار

1. زد رقم الإصدار، واكتب ملاحظات واضحة، واختبر الحزمة على نظام التشغيل
   المستهدف.
2. اختبر الترقية من إصدار أقدم وتأكد من حفظ قاعدة البيانات والنسخة الاحتياطية.
3. اختبر فشل الشبكة والتنزيل، ثم تحقق من أن إعادة المحاولة تنجح ولا يُثبّت
   ملف غير مكتمل.
4. انشر الأصول إلى GitHub Release المطابق، وتأكد من ظهور ملفات التحديث
   والـ hashes والتوقيعات الصحيحة.
5. اختبر التحديث من قناة الإصدار المنشور على جهاز نظيف، ثم راقب سجلات updater
   وبلاغات أخطاء التطبيق بعد النشر.

يسجل التطبيق أخطاء الفحص والتنزيل في سجل Electron (`[updater]`). احتفظ بهذه
السجلات عند تشخيص مشكلة، ولا تجمع رموز الوصول أو بيانات العملاء معها.
