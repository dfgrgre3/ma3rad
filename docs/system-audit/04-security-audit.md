# 04 — تدقيق الأمان

> **النطاق:** أمان العملية الرئيسية في Electron، جسر IPC، تشفير قاعدة البيانات، المصادقة والصلاحيات، سجل التدقيق، النسخ الاحتياطي، والتحديثات.
> **المنهج:** مراجعة كود + قراءة اختبارات الأمان + فحص تكوين البناء.

---

## 1. نموذج التهديد المختصر

| التهديد | الأثر المحتمل | الضوابط القائمة |
|---|---|---|
| تنفيذ كود من Renderer | سيطرة كاملة على الجهاز | `sandbox`, `contextIsolation`, منع `nodeIntegration`, CSP صارم، تعقيم IPC |
| حقن SQL | قراءة/تعديل بيانات | استخدام استعلامات مُعاملة (Prepared) + `IDENTIFIER` whitelist |
| سرقة ملف القاعدة | تسريب بيانات مالية | AES-256-GCM + مفتاح محمي بـ `safeStorage` |
| تصعيد صلاحيات | عمليات غير مصرّح بها | تحقق داخل الخدمات + DENY يتقدّم + قيود مركزية |
| تخمين كلمات المرور | اقتحام حساب | bcrypt + قفل تدريجي + سياسة كلمات مرور |
| فقدان البيانات | توقف العمل | نسخ احتياطي محلي/خارجي + مفتاح استرداد + تحقق سلامة |
| تحديث خبيث | تنفيذ كود | توقيع إلزامي + التحقق من بصمة التحديث |

## 3. تشفير قاعدة البيانات

- الترويسة: `CERAMISYS-DB\0v1\0` ثم IV + Tag + Ciphertext.
- الخوارزمية: **AES-256-GCM** (سرية + سلامة).
- المفتاح: 32 بايت عشوائي، مشفّر عبر `safeStorage` (Windows DPAPI) في `database-key.enc`.
- مفتاح الاسترداد: scrypt (N=32768, r=8, p=1) + AES-256-GCM.
- فحص `PRAGMA integrity_check` قبل قبول أي استيراد/استعادة.
- النسخ الاحتياطي لا يكتب فوق آخر نسخة سليمة عند فشل الكتابة (اختبار `database-durability`).

**تقييم:** جيد جداً لتطبيق سطح مكتب محلي. القيد الوحيد أن `safeStorage` مرتبط بجهاز/حساب Windows؛ لذلك مفتاح الاسترداد ضروري عند نقل الجهاز.

## 5. الصلاحيات

- كتالوج من **4,313** صلاحية دقيقة (3,892 واجهة + 421 خدمة/وحدة).
- وراثة `module.*` و`*` مع أولوية **DENY** على مستوى المستخدم.
- قيود المنصة المركزية (`CentralFeaturePermissionService`) تُطبّق قبل صلاحية الدور في طبقة الواجهة.
- الصلاحيات المدمجة: ADMIN، MANAGER، CASHIER، WAREHOUSE، ACCOUNTANT، VIEWER (6 أدوار).
- **الحذف/العمليات المدمّرة** محصورة بـ ADMIN افتراضياً (اختبار `permissions`).
- كل صفحة لها `ui.<page>.view`؛ الأدوار غير الإدارية لا تحصل على صلاحيات مدمّرة عند الترقية.
- العمليات الحساسة في الخدمات تستدعي `PermissionService.require` (مثال: `ui.sales.invoices.discount`, `ui.purchases.invoices.delete`).

**تقييم:** طبقة الصلاحيات ناضجة ومغطاة اختبارياً. المخاطرة المتبقية هي أي دالة خدمة جديدة تُنسى فيها `require`.

## 6. حقن SQL

- الاستعلامات تستخدم `?` في كل مكان تقريباً.
- الاستثناءات المقصودة هي أسماء جداول/أعمدة ديناميكية، ومحمية بـ:
  - `IDENTIFIER` regex في `DataAdminServicePart01.ts:10`.
  - قوائم أعمدة ثابتة مُعرّفة في الكود (`BatchService`, `BranchService`, `ManufacturingService`, `WarrantyClaimService`).
- لا توجد أي حالة تمرير مدخلات مستخدم مباشرة إلى SQL دون قائمة بيضاء.

---

## 7. سجل التدقيق

- `audit_logs` + `domain_events` يسجّلان: المستخدم، العملية، الكيان، القيم القديمة/الجديدة، الفرع، الشركة، الوقت.
- `AuditService` يفرض صلاحية `audit.view`.
- العمليات المالية (بيع/شراء/مرتجع/شيك/راتب/أصل ثابت/شريك) تكتب حدثاً داخل نفس المعاملة.
- القيود المحاسبية تحتفظ بـ `created_by` و`branch_id` و`company_id`.

---

## 8. النسخ الاحتياطي والاسترداد

- نسخ محلية مجدولة + نسخة خارجية اختيارية (Offsite).
- التحقق من النسخة قبل اعتمادها (`integrity_check`).
- تشفير نسخ XLSX بكلمة مرور عند الحاجة.
- مفتاح استرداد يُصدَّر بكلمة مرور.
- اختبارات: `backup-strategy.test.cjs`, `backup-encryption.test.ts`, `backup-restore.test.ts`, `database-recovery.test.ts`.

## 9. التحديثات والتغليف

- `electron-builder` مع `forceCodeSigning: true` و`verifyUpdateCodeSignature: true`.
- ناشر GitHub محدد مسبقاً.
- لا يتم تنزيل تحديث غير موقّع.
- `bytenode` لحماية الكود (طبقة إضافية وليست بديلاً عن الأمان).
